This is for the Style Assist app.

Home screen and GenerateOutfitScreen must stop using mock wardrobe data when real wardrobe items exist.
Use the wardrobe items the user has added/captured.
If wardrobe is empty, show the existing empty wardrobe state and guide the user to add their first item.
If wardrobe has items, outfit generation should build from those items only.
Keep fallback demo data only for development/demo mode, never as the default user experience.

Priority 2: Add app-level error boundaries.
Add a reusable ErrorBoundary component.
Wrap the main app routes/screens so a component crash shows a calm premium fallback screen instead of a blank white page.
Fallback copy should feel like Style Assist:
“Something didn’t load properly.”
“Your wardrobe is safe. Please try again.”
Include a Try Again button.

- real user wardrobe stats, such as number of saved items, outfits generated, saved looks
or

Priority 4: Add loading, empty, and offline states.
Add graceful states for:
- no wardrobe items
- outfit generation loading
- failed outfit generation
- no internet connection
- image/item loading failure
Keep the wording calm, premium, and helpful.

Priority 5: Accessibility polish.
Add aria-labels or accessible labels to all key buttons, tabs, icon buttons, wardrobe item cards, save buttons, generate buttons, and navigation controls.
Do not visually change the interface unless needed.
